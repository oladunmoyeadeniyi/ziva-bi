## Issues Found

**`frontend/src/app/invite/accept/page.tsx` — the fix does not actually resolve the build error.**

The brief's premise was that `export const dynamic = "force-dynamic"` would stop Next.js from
attempting to statically prerender this route, avoiding the `missing-suspense-with-csr-bailout`
error. This is not just a type/lint issue, so `tsc --noEmit` and `eslint` (both of which the brief
asked to run, and both of which pass) cannot catch it — it only surfaces during an actual
`next build`. I ran the real production build rather than relying on the brief's claim, and it
still fails with the exact same error:

```
 ⨯ useSearchParams() should be wrapped in a suspense boundary at page "/invite/accept".
   Read more: https://nextjs.org/docs/messages/missing-suspense-with-csr-bailout
Error occurred prerendering page "/invite/accept". Read more: https://nextjs.org/docs/messages/prerender-error
Export encountered an error on /invite/accept/page: /invite/accept, exiting the build.
 ⨯ Next.js build worker exited with code: 1 and signal: null
```

Root cause: `AcceptInvitePage` (the page's default export, `page.tsx:50`) calls
`useSearchParams()` directly in its own render body (`page.tsx:51`). Next.js's build-time
static-generation analysis flags this specific pattern — a component calling `useSearchParams()`
with no ancestor `<Suspense>` boundary — independently of the route's `dynamic` segment config.
`force-dynamic` tells Next not to *cache* the route, but Next still performs this build-time
validation pass before it will treat the route as dynamic, and the validation fails whether or not
`dynamic` is set. (This matches the officially documented fix on the linked Next.js page: wrap the
component that calls `useSearchParams()` in `<Suspense>`, not just mark the route dynamic.)

**Suggested fix for Cowork:** split `page.tsx` into two pieces —
1. An inner component (e.g. `AcceptInviteContent`) containing all of the current
   `AcceptInvitePage` body, including the `useSearchParams()` call.
2. A new default-export `AcceptInvitePage` that renders
   `<Suspense fallback={...}><AcceptInviteContent /></Suspense>`.

The `export const dynamic = "force-dynamic"` line added in this commit is not harmful and can
stay (it's still semantically correct — this page must never be served from a static cache — but
it is not sufficient on its own and does not need to be removed).
