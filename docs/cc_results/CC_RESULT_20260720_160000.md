## Issues found (blocking)

### All-advisory selective_tree chain can leave a report permanently stuck, with no error surfaced anywhere
Traced the full `approve()` flow in `backend/app/routers/approvals.py`. When `approval.is_advisory`
is `True`, the function takes an early-return branch (lines 2231–2244): it marks the step approved,
writes `EXPENSE_ADVISORY_REVIEWED`, and returns immediately — **it never touches `next_blocking`,
never advances `current_approval_level`, and never triggers GL posting.** The only code path that
finalizes a report (the `next_blocking is None → post_expense_to_gl(...)` branch, line 2369) lives
inside the **non**-advisory branch.

Consequence: if a `selective_tree` policy has every selected designation marked `"role": "review"`
(none `"approve"`), and finance review is disabled or `finance_levels == 0`, then **every**
`ExpenseApproval` record created for that submission has `is_advisory=True`. Every reviewer can sign
off (each hitting the early-return branch), but nothing ever computes `next_blocking`, so the report
never advances past its initial `current_approval_level` and never posts to GL. It's stuck
permanently — no exception, no stuck-report detection, nothing visible to the submitter, the
reviewers, or an admin. This is a worse failure mode than the earlier `selective_tree` bug (which at
least surfaced a clean 422 immediately) because it fails silently, potentially long after submission.

I confirmed this is reachable through the actual UI, not just a theoretical code path: grepped
`approval-matrix/page.tsx` for a guard requiring at least one `"approve"`-role designation — there
is none. The only existing validation (both frontend, line 625, and backend,
`approval_routing.py` line 443) is "at least one designation selected," which says nothing about the
`approve`/`review` split. An admin can save an all-review policy today with no warning.

**Recommended fix** (mirrors the existing "no designations selected" guard style already in this
file): in `compute_chain()`, after the chain is fully built (management + finance), add —
```python
if not any(not step.is_advisory for step in chain):
    raise ApprovalRoutingError(
        "This approval policy has no blocking approver — at least one designation level must be "
        "set to 'Approves', or finance review must be enabled with at least one level."
    )
```
This surfaces the misconfiguration as a clean 422 at submit time (consistent with every other
config-error path in this function), rather than letting the report silently vanish into limbo.
