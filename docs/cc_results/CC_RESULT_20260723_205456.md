## Issues Found

### 1. `backend/app/routers/auth.py` — `NameError` on every real `forgot-password` call
`forgot_password()` (new function, ~line 943) references `settings.frontend_url` to build the reset URL, but `settings` is never imported at module level in this file — it's only imported *locally* inside two unrelated functions (`login` at line 183, `refresh_token` at line 634). The new `forgot_password` function has no local `from app.config import settings` either. Any request for an **existing, active** user will hit `NameError: name 'settings' is not defined` inside the `if user and user.is_active:` block, after the token has already been committed to the DB — the user gets a 500, but a `PasswordResetToken` row is silently created and orphaned (email never sent, token unusable since the user never receives it).
- This wasn't caught by `py_compile` or the import-time check (both pass clean) because it's a runtime-only NameError inside a conditional branch — confirmed by running both checks below.
- Fix: add `from app.config import settings` at module level (or locally inside `forgot_password`, matching the file's existing local-import convention).

### 2. `frontend/src/app/auth/reset-password/page.tsx` — missing `Suspense` boundary around `useSearchParams()`
`ResetPasswordPage` calls `useSearchParams()` directly in the default-exported component with no `<Suspense>` wrapper. Next.js 15 App Router requires any component using `useSearchParams()` to be wrapped in `<Suspense>` for static/prerendered pages — without it, `next build` fails at the prerender step for `/auth/reset-password` (well-established Next.js constraint; this exact pattern was already fixed on 6 other pages in the "UI Polish Phase 2 — Build E" milestone, see `MASTER_CONTEXT.md` §5, and the reference pattern lives in `frontend/src/app/dashboard/business/approvals/page.tsx`).
- `tsc --noEmit` passes clean (confirmed below) because this is a Next.js build-time constraint, not a TypeScript type error — so the brief's own "TSC check on the two new frontend pages" verification step could not have caught it.
- Fix: split into an inner component that calls `useSearchParams()`, and export a wrapper that renders `<Suspense fallback={...}><ResetPasswordInner /></Suspense>`, matching the existing pattern in `approvals/page.tsx` / `setup/currencies/page.tsx`.

**Both are launch-blocking for a real deploy**: #1 breaks every password-reset request from an active user (silently — the caller gets a generic 500, no diagnostic), #2 breaks the entire Render frontend build (P1 — Production Deployment — is the #1 priority in `MASTER_CONTEXT.md` TIER 0, so this would block the very next deploy).

AND used_at IS NULL` queries back to back (first result is discarded, `old_tokens_res` is the one actually used).
