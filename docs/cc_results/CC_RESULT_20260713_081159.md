## Issues Found

### 1. BLOCKING — `/api/setup/org` never returns the real `posting_mode`, so every guard in this brief is dead code

`backend/app/routers/setup.py`, `_org_to_response()` (lines 284-314, shared by both `GET /api/setup/org`
and `PATCH /api/setup/org`) builds `OrgConfigResponse(...)` from the `TenantOrgConfig` ORM object but
never includes `posting_mode` in the constructor call. `OrgConfigResponse` (schema, line 132) declares
`posting_mode: str = "full_erp"` — since the builder never sets it, every response silently falls back
to that Pydantic default, regardless of what the tenant's actual `posting_mode` column value is.

Confirmed empirically, not just by reading:
```python
>>> from app.routers.setup import _org_to_response
>>> from app.models.setup import TenantOrgConfig
>>> fake_org = TenantOrgConfig(tenant_id=uuid.uuid4(), posting_mode='lite')
>>> resp = _org_to_response(fake_org, fake_org.tenant_id)
>>> resp.posting_mode
'full_erp'
```
Even with the ORM object's `posting_mode` explicitly set to `'lite'`, the response reports
`'full_erp'`.

Every new frontend guard in this brief (`layout.tsx`'s 5 sidebar links, the 5 page-level
`ModeNotAvailable` gates, `expense-config`'s coding-level lock) reads `data.posting_mode` from this
exact endpoint and checks `postingMode !== 'lite'` (or `=== 'lite'` for the lock). Since the endpoint
can never actually report `'lite'`, none of these guards will ever fire for a real Lite tenant — the
sidebar links stay visible, direct navigation never shows the mode gate, and the expense-config
cards never lock. The feature is fully non-functional as submitted, for every tenant, always.

**Fix needed** (this does require touching `backend/app/routers/setup.py`, despite the brief's
"No backend changes" framing — the assumption that the field was already wired up was incorrect):
```python
def _org_to_response(org: Optional[TenantOrgConfig], tenant_id: uuid.UUID) -> OrgConfigResponse:
    if org is None:
        return OrgConfigResponse(tenant_id=str(tenant_id))
    return OrgConfigResponse(
        tenant_id=str(org.tenant_id),
        ...
        org_configuration=org.org_configuration,
        posting_mode=org.posting_mode,   # <-- add this line
    )
```
One line. No migration needed — `TenantOrgConfig.posting_mode` already exists as a column (confirmed
used elsewhere, e.g. `platform.py`'s `system-config` endpoints). After this fix, re-verify by
actually calling `_org_to_response` with a `posting_mode='lite'` object the same way I did above and
confirming the response now also says `'lite'`.
