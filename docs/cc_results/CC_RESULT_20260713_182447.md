## This round: verified the fix for the last round's non-blocking finding

Last round I flagged that the brief's claimed "mode gate banner as safety net" was actually dead
code — `visibleModules` filtered out *all* incompatible modules (licensed or not) before they could
ever be selected, so the banner and the deactivate-only fallback could never fire, and a module
active under Full ERP that later became incompatible (mode downgraded to Lite) would vanish from
the page entirely with no way to deactivate it there.

This round's fix, read in full and traced end-to-end:
```ts
const visibleModules = modules.filter(
  (m) => m.is_licensed || isAvailableForMode(m.module_key, postingMode)
);
```
Licensed-but-incompatible modules now stay in `visibleModules` (hence in `subscribed`), rendering
with the amber-warning `ModuleCard` state. Clicking one sets `selectedMod` to that module — now
reachable, since it's actually rendered — which correctly triggers both the amber mode-gate banner
and the deactivate-only button branch (`isAvailableForMode(...) ? <Activate/Deactivate> :
selectedMod.is_active ? <Deactivate-only> : null`). Unlicensed-and-incompatible modules remain
correctly hidden from `available`. Traced the remaining edge case (licensed, incompatible, and
never activated) too: the ternary renders no Activate/Deactivate button, but "Remove from
subscription" sits outside that ternary and is always available to SA — no dead end.
