## Fix verified (blocking issue from the previous review)

Confirmed fixed in this round (`gl_reporting.py` lines ~753–775):
- Cash accounts (`cat == "cash"`) now `continue` at the top of the loop, before any wasted `cf_amt` computation. `opening_cash_raw` only accumulates `if opening_date is not None` — correctly zero for the all-time case.
- BS-account branch now uses `opening_bal = (await _bs_balance_at(...) if opening_date is not None else _ZERO)` — opening balance is explicitly zero when there's no period start, matching the function's own documented contract.
- No remaining call passes `None` as the *opening* bound anywhere in the loop. (`_bs_balance_at(..., date_to)` for the closing bound legitimately allows `date_to=None` — that's correct "all posted entries to date" semantics, unrelated to the bug.)
