## Architectural notes (non-blocking)
- `ApprovalPolicyCreate.requires_finance_review` default flipped from `True` to `False`. Not
  disclosed in the brief, but confirmed inert in practice — `approval-matrix/page.tsx` always
  explicitly sends this field (line 342), so the schema default only matters for a hypothetical
  direct API caller that omits it. Worth a one-line mention in the commit description next time,
  but not a functional risk today.
- `ceiling_role_id` / `finance_l1/l2/l3_role_id` columns are kept on the model "for backward compat
  (not used by routing service)" rather than dropped. Reasonable soft-deprecation to avoid extra
  migration churn now, but these are dead weight going forward — worth a follow-up migration to drop
  them once nothing references them, so the schema doesn't silently carry two parallel (one dead)
  representations of the same concept.
- The designation-fallback query for finance step assignees (`ApprovalRole.designation ==
  fs.assigned_designation`, `.limit(1)`) has no `ORDER BY` before the limit — if a tenant somehow has
  multiple active employees at the same designation, which one gets picked is DB-order-dependent
  (nondeterministic across runs). Low practical impact (finance designations are typically 0-or-1
  person per tenant), not blocking.
- `formatMoney`'s default `₦` symbol is never overridden at any of the ~12 call sites converted in
  this diff — but this exactly matches the prior behavior of the local `formatNGN` functions being
  removed (also hardcoded to Naira, per their name). Not a new regression, just a pre-existing
  multi-currency gap being centralized rather than fixed. Worth flagging for whenever this codebase
  does its multi-currency display pass (tracked already in `PROJECT_STATE.md` §6 as JSONB-only /
  UI-built).
