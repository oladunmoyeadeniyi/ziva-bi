## Security review (this module touches an external AI API and file uploads — reviewed with extra care)
- **API key handling:** `ANTHROPIC_API_KEY` sourced exclusively from `settings.anthropic_api_key` (pydantic-settings, env-var backed). `render.yaml` entry uses `sync: false` (manual entry in Render dashboard, never committed). `.env.example` ships blank. Default `""` triggers a graceful `OCRNotConfiguredError` → HTTP 501, not a crash. Consistent with the existing `RESEND_API_KEY` pattern in this codebase.
- **Tenant scoping:** `POST /api/ai/ocr` requires `current_user.tenant_id`; `ocr_enabled` flag checked per-tenant before any API call is made. `POST /api/ai/override` explicitly re-verifies the referenced `prediction_id` belongs to `current_user.tenant_id` before writing — correctly prevents one tenant from polluting another's `ai_predictions` audit trail via a guessed UUID (an IDOR check that's easy to skip and wasn't skipped here).
- **File validation:** MIME allowlist (JPEG/PNG/WEBP/PDF) and 10 MB size cap enforced in *two* places independently — the router (`_detect_mime`, explicit size check) and the service (`SUPPORTED_MIME_TYPES`, `MAX_FILE_BYTES`) — defense in depth.
- **One non-blocking gap noted:** unlike the established `expense_documents` upload path (magic-byte + ZIP-structure validation per `MASTER_CONTEXT.md` §3's documented invariant), this upload trusts the filename extension / `content_type` header rather than inspecting actual file bytes. Low severity here specifically because the file is never persisted to storage — it's read into memory, forwarded to the Anthropic API, and discarded; worst case is a wasted API call or a low-confidence extraction, not a stored-file attack surface. Worth aligning with the stricter pattern if this module later adds persistent storage of the uploaded receipt image.
- **Audit trail integrity:** every OCR call writes an `ai_predictions` row before returning a response — no path returns extracted data without an audit record.
