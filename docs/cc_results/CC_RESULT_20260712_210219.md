## Issues Found

### 1. CRITICAL — `POST /api/platform/tenants` ("Create Company", Issue 1) crashes on every call

`backend/app/routers/platform.py`, inside `create_tenant()` (new endpoint, ~90 lines added at the
end of the file):

```python
from app.core.security import get_password_hash
...
admin_user = User(
    email=admin_email,
    full_name=data.admin_full_name.strip(),
    hashed_password=get_password_hash(data.admin_password),
    account_type=AccountType.business,
    is_active=True,
    is_verified=True,
    is_super_admin=False,
)
```

Two stacked bugs, both confirmed empirically (not just read):

- **`get_password_hash` does not exist.** `app/core/security.py` only defines `hash_password`
  (confirmed via `grep "^def "` — only `hash_password`, `verify_password`, `create_access_token`,
  `decode_access_token`, `generate_refresh_token`, `hash_refresh_token`). This import is local to
  the function body, so it doesn't break the router's module-level import (which is why
  `python -c "from app.routers.platform import router"` in Step 4 passes clean) — it raises
  `ImportError` the instant `create_tenant` is actually invoked.

- **Even with that renamed, `User(...)` would still crash.** `User` (`app/models/auth.py:150-186`)
  has no `hashed_password` or `is_verified` column at all — confirmed empirically:
  `User(hashed_password=..., is_verified=..., ...)` raises
  `TypeError: 'hashed_password' is an invalid keyword argument for User`. The password hash lives
  on **`UserTenant.password_hash`**, per that model's own docstring ("Stores the password hash
  here so the same person can have different credentials per company") — this is the exact
  multi-tenant password architecture the codebase already uses everywhere else, including in this
  same router's sibling function `signup()` in `auth.py`:
  ```python
  user_tenant = UserTenant(
      user_id=user.id,
      tenant_id=tenant.id if tenant else None,
      password_hash=hash_password(data.password),
  )
  ```
  `create_tenant`'s own `UserTenant(...)` call three lines later sets `user_id`, `tenant_id`,
  `role_tier`, `is_active` — but never `password_hash`. So even after fixing the two bugs above,
  the created admin account would have `password_hash = NULL` and could never log in.

**Net effect:** the star feature of this whole PR — the SA "Create Company" button, both backend
and the frontend modal that calls it — is completely non-functional. Every attempt to create a
tenant this way will 500.

**Fix needed** (mirrors `auth.py`'s own `signup()` pattern exactly):
```python
admin_user = User(
    email=admin_email,
    full_name=data.admin_full_name.strip(),
    account_type=AccountType.business,
    is_super_admin=False,
)
db.add(admin_user)
await db.flush()

db.add(UserTenant(
    user_id=admin_user.id,
    tenant_id=tenant.id,
    role_tier="power_admin",
    is_active=True,
    password_hash=hash_password(data.admin_password),
))
```
(`hash_password` is already imported at the top of `auth.py` from `app.core.security` — `platform.py`
needs its own import added.)
