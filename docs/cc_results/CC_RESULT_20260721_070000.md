## Architectural notes
This is a correct, well-known Render deployment pattern: `buildCommand` runs before the service's
own environment (including `DATABASE_URL` resolved from the linked database) is guaranteed
available, while `preDeployCommand` runs after the build completes and immediately before the start
command, with the DB connection fully resolvable. Running `alembic upgrade head` at build time risks
an intermittent failure if the linked DB service isn't fully initialized yet; running it as
`preDeployCommand` is the pattern Render itself documents for this exact use case.

This is the fourth consecutive render.yaml-only commit, each fixing a distinct real deployment issue
(standalone start command, DB plan, invalid property name, now migration timing) — consistent with
