## Architectural notes
This resolves last round's blocking security concern the right way: rather than disabling
certificate verification (`CERT_NONE`), the fix loads `certifi`'s actively-maintained Mozilla CA
bundle explicitly via `ssl.create_default_context(cafile=certifi.where())`. This is exactly the
recommendation from the prior review — `certifi` was already confirmed present (transitive
dependency of `httpx`, itself a direct `requirements.txt` entry), so no new dependency was needed.
The diagnosis (Render's minimal Python runtime shipping an incomplete OS-level CA bundle, producing
the same "self-signed certificate" error as a genuinely unverifiable cert) is a well-known class of
issue in containerized deployments, and this is the standard, correct fix for it — full verification
preserved, no security tradeoff accepted.
